# V3.5.1 — Governed Agent Execution Bridge

Engineering work item: https://github.com/patricktbann/Patrick-OS-Command-Centre/issues/2

## Truthful task states
- DRAFT: browser-local staff task, no backend action.
- ASSIGNED: real accepted assignment with repository and task ID.
- EXECUTING: executor run ID exists and backend confirms work began.
- OUTPUT_READY: commit or PR exists; output not yet accepted.
- QA_FAILED / QA_PASSED: documented tests and reviewer evidence.
- UAT_PENDING: awaiting Patrick's review.
- APPROVED / REJECTED: explicit decision recorded.
- COMPLETE: only after required approval.

Each task must retain the assigned staff ID, division, company workspace, scope, permitted tools, prohibited actions, human approval gate, source repository, execution context, run references, QA records and an append-only audit trail.

The GitHub Pages application is public and cannot hold private keys or execute private-repository work itself. A secure authenticated backend or connected Codex workflow is needed. Ability sliders describe staff requirements; they do not change underlying model intelligence.

## Pilot
Run a harmless issue-driven implementation in the public command-centre repository, require an identifiable execution run, proposed branch or PR, tests and explicit QA. No production deployment, merge, paid service activation, or modification of private ERGI / ERP repositories.
