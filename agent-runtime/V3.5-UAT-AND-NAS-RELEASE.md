## Stage A — Development readiness (no NAS required)
1. Review stacked PR merge chain, compatibility and release notes. Resolve overlapping PRs carefully; never squash the wrong base branch.
2. Check all Node tests and disposable PostgreSQL CI, confirm the full review branch matches proposed artifacts.
3. Independent backend session authentication: deny public/client flags and verify real Patrick principal authority.
4. Durable task-specific approval and revocation proof. Evidence must bind immutable task digest, company, division and repository.
5. Configure a private development host and a real authorized Codex SDK session through ChatGPT login **without enabling separate API-key billing**.
6. Run genuine read-only SDK pilot. Validate real thread ID, repository SHA, output and no changes to working tree.
7. Integrate runtime using an authenticated private executor, not GitHub Pages JS or CI mock providers.
8. Prove one non-destructive task end-to-end; confirm audit and safe failure recovery with no duplicate execution.

## Stage B — Patrick UAT
- UAT-A: assignment scopes only the selected company/division/agent.
- UAT-B: fake or changed task, principal identity and approval always denied.
- UAT-C: real read-only Codex execution includes authenticated source and run evidence.
- UAT-D: agent produces QA-verifiable output; completion state isn't self-asserted.
- UAT-E: timeouts are quarantined until confirmed by independent run lookup; duplicate requests never trigger two runs.
- UAT-F: controlled draft-PR test only after separately approved permissions; merge and deploy actions blocked.
- UAT-G: Patrick reviews actual output in V3.5 preview and explicitly signs off functional acceptance.
- UAT-H: backup, restore, private networking and disaster recovery policy documented.

## Stage C — Freeze and NAS migration (AFTER A+B)
- Confirm NAS brand/model/CPU/RAM/container runtime before choosing target platform.
- Produce pinned software/image versions, environment variable template **without credentials**, backup & restore playbook and rollback release tag.
- Provision private storage and trusted identities, restricted outbound network and least privilege; avoid publishing NAS administration/DB ports to internet.
- Migrate using a controlled database migration with backup and rollback point. No paid services or production changes without Patrick approval.
- Re-run smoke tests, authorized SDK execution, audit checks, restoration rehearsal, and Patrick production acceptance.

## Machine-readable verification
`agent-runtime/release-gates.mjs` evaluates independently provided release evidence with a default **HOLD**. Even when all checks are recorded, the result is only `READY_FOR_MANUAL_RELEASE_APPROVAL`; it never merges/deploys automatically. The evaluator is an evidence-schema gate, not an independent authenticator: a trusted reviewer must verify evidence provenance and Patrick's consent.

**Release status:** HOLD until actual SDK authentication, real private backend integration, Patrick UAT and NAS compatibility are proven.
